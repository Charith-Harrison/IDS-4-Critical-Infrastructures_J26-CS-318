Open DATASET_CARD.md, HANDOVER.md and the supplied run's EVIDENCE_WALKTHROUGH.txt
first. The verified recording was collected on Thithira's PC. You do not need to
regenerate it or install Docker just to read the supplied evidence. The steps
below are for running a NEW pilot or rechecking via the Docker environment.

1. Install Docker Desktop for Windows from the official instructions:
   https://docs.docker.com/desktop/setup/install/windows-install/
   Use WSL2/Linux containers. Restart if requested. Open Docker Desktop and
   wait for its engine to run. Follow actual installer errors rather than
   guessing system/BIOS changes.

2. Extract this package into your repository so there is exactly:
   IDS-4-Critical-Infrastructures_J26-CS-318\component3_testbed_pilot\README.md
   Keep existing component3_preparation and component3_reassessment folders.

3. Open your repository in Codex. Open PowerShell at the repository root.
   Type these ONE AT A TIME:

   Set-Location .\component3_testbed_pilot
   .\start-pilot.ps1 -CheckOnly

4. If that check succeeds:

   .\start-pilot.ps1

   First build downloads required software. The experiment runs offline.
   It prints a NEW outputs\pilot-... folder. Keep the exact name.

5. Run the verifier using the ACTUAL folder name:

   .\verify-pilot.ps1 -Run pilot-20261024T120000Z-a1b2c3d4

   The name above is only an example. Verification also prints a short
   evidence walkthrough showing normal/attack messages with matching PDUs.

6. Open validation_report.json in that run folder. A passing report should
   have status PASSED and counts 208 normal / 4 command / 4 response for
   the default pilot. These are application messages, not raw packet counts.

7. Discuss one command and one response example with Thithira using
   docs\DISCORD_LESSON.md. Send the actual report/status for review.

8. Stop there. No bulk collection, random split, preprocessing or ML yet.
   Explain the toy assumptions and agree the larger experiment's scope first.
