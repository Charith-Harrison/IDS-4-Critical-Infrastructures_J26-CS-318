# Component 2 handoff: what comes from where

A second Windows laptop gets the same functional Component 2 state as the development machine from two sources:
**Git** and **one package**. The only meaningful difference is the raw acquisition archive, which is not needed for
the viva. The exact file list, sizes and SHA-256 hashes are in `HANDOFF_MANIFEST.json`, which is generated by
`demo/build_handoff.py`, shipped inside the package and checked by `setup_c2_demo.ps1`.

## 1. Obtained from Git (`branch-ghost`)

All tracked source and documentation:

* `component2_testbed/` (code, configs, protocols, results summaries, frozen plan manifest);
* `C2_Reconnaissance_Detection/` (new frontend source, demo backend, scripts, guides);
* `component2_forensic_review/` and `component2_recon_audit/` (audit reports and tables);
* the legacy CIC code.

## 2. Transferred separately: `C2_handoff_package.zip`

Extract it into the repository root. Every file below is Git-ignored, so `git pull` alone does not provide it.

| Group | Contents | Why it is needed |
|---|---|---|
| `C2_Reconnaissance_Detection/demo_bundle/` | Frozen models, LSTM weights, thresholds, 8 prepared held-out runs, upload samples (CSV/Parquet) with reference scores, final reports | Frontend and backend runtime |
| `C2_Reconnaissance_Detection/frontend/dist/` | Built React frontend | Served by the demo server; no Node.js needed |
| `component2_testbed/data/final_v1/models/` | Fitted models, thresholds, CV selection, validation/test scores and reports, test-opening logs | The frozen model artifacts and final results |
| `component2_testbed/data/final_v1/model_inputs/` | Exact train/validation/test inputs | Re-running or inspecting training and selection |
| Collection evidence | Collection manifests, gate results, per-run acceptance, tshark and parse summaries, run manifests with PCAP hashes, logs | Validation evidence for all 384 runs |
| Pilot evidence | Pilot v1–v3 summaries, gates and diagnostics | The design-iteration history |
| Raw evidence of the 8 prepared runs | PCAPs, ledgers, plans, clock logs, parsed tables | Wireshark proof and re-parsing for the demo runs |

## 3. Optional raw evidence, not required for the viva (stays on the development machine)

| Omitted | Why it is unnecessary |
|---|---|
| Raw captures, ledgers and plans of the other 376 final runs (~1.7 GB) | Not used by the demo, the models, replay, scoring or training. Every PCAP hash is in the shipped run manifests. |
| Per-run parsed tables of those runs (~0.4 GB) | Regenerable from the raw captures; the model inputs derived from them are shipped. |
| Pilot raw runs and bulk pilot tables (~0.4 GB) | Pilot summaries and gates are shipped. |
| Smoke-test collections | Tooling checks, excluded from every analysis. |
| Frozen plan bodies (~0.3 GB) | Regenerated byte-identically by `c2tb.freeze_plans`; hashes are tracked. |
| Superseded packages | Replaced by this package. |
| `demo/.venv`, `frontend/node_modules`, the forensic audit's `.deps` | Environments, recreated by setup, npm or pip. |
| CIC-audit bulk evidence (~0.5 GB) | Intermediate files regenerable only with the external 15.6 GB CIC archive. Reports are tracked. |

## External dependencies that remain on the development machine

* **Forensic audit scripts.** `component2_forensic_review/scripts` reference the original CIC archive
  (`G:\modbus cic 2023`) and the original attachments. Re-running that audit needs those external sources; the viva
  does not.
* **Docker images.** Only needed to re-collect traffic or retrain:
  * `c2-recon-testbed:0.1.0` is built from `component2_testbed/docker/Dockerfile`;
  * `c2-recon-model:0.1.0` is built from `component2_testbed/docker/Dockerfile.model`.

  The demo and inference need neither.
